## 1. 想法：用 RQ-KMeans 码本初始化新增 token 的 embedding

**状态（2026-09-16）：已实现并实验完毕（E1–E5）。**

> **结论**（详见 [LoRA与码本初始化实验.md](LoRA与码本初始化实验.md) §8 / `PROGRESS.md` 2026-09-16 节）：
> 码本初始化**对 LoRA 是决定性的**（HR@50 从全参的 86.1% → **99.2%**；HR@1 37.4% → 91.3%），
> **而在全参侧未观察到收益**（HR@50 −1.79%，各指标一致地低 1–2%，单 seed 下未验证显著性）。
> 两者对比支持「码本先验主要缓解低秩适配下的优化负担，全参对初值不敏感」，
> 但**尚不能断言根因就是"容量不足"** —— 表示容量 / 优化受限 / 超参未调优三者在现有实验中不可区分。
> 打乱码本对照（E5）表明主效应是「把新 token 放进 SID 该在的向量区域」，精确的 token↔向量对应
> 叠加一个小而稳定的增量。
>
> **本节以下保留实验前（09-14/09-15）的原貌**，不改写 —— 其中的推理链和实测数据是结论的来源。

### 1.1 接口

```bash
# 全参 SFT
python sft.py ... --init_new_emb codebook [--codebook_path <path>]

# LoRA（走 sft_lora.sh 的环境变量）
INIT_EMB=codebook OUTPUT_ROOT=./outputs_sft_lora_cb bash sft_lora.sh
```

- 默认路径从 `sid_index_path` 同目录推导：`.codebooks_constrained.npz` / `.codes_constrained.npy`
- ⚠️ **必须配独立 `OUTPUT_ROOT`**（`sft_lora.sh:87` 会在用默认输出目录时告警）——否则会覆盖 `resize` 基线的 `final_checkpoint`
- 实现位置：`sft.py::init_new_emb_from_codebook`

### 1.2 动机与实测证据

RQ-KMeans 码本（`codebook_0/1/2`，shape `(256, 1024)`）与 Qwen3-0.6B 的 `hidden_size` 同为 1024。**两空间不是"维度凑巧相同"，而是语义结构实质对齐**（2026-09-14 实测）：

| 检验 | 结果 | 随机基线 |
|---|---|---|
| 线性对齐留出 R²（PCA→64 + 岭回归） | **0.4032** | −0.0348（打乱） |
| 相似度结构 Spearman | +0.2160 | −0.0007 |
| level-0 簇命中率 | **47.3%** | 0.39%（122×） |
| level-1 严格检验（固定 `<a_x>` 上下文） | **82.4%** | 25.0%（3.3×） |
| level-2 对角/非对角 cos 对比 | 0.0517 / −0.0000 | — |

⚠️ **测量教训**：第一次测得 R² = −0.12（"无对齐"）是**设计错误**——1333 样本拟合 1024 维、正则化过小导致过拟合。降维 + 扫正则后**符号相反**。**n<d 的回归必须降维或强正则，否则会得到假阴性。**

### 1.3 两个必须处理的细节

**① 尺度：目标是 resize 默认初始化的范数（≈0.30），不是老词表范数（0.926）** ⚠️ 2026-09-15 修正

码本原始范数：level0 = 65.9 / level1 = 11.2 / level2 = 8.2（比老词表大 71×）→ 必须重标定。
**但重标定的目标尺度初版选错了**（选了 `old_norm` = 0.926，即训练过的老词表行范数）。实测代价：

| 目标范数 | 新 token 区间 logits mean/std/max | 首步 loss |
|---|---|---|
| resize 基线（MVN 初始化） | +3.55 / 3.20 / 10.50 | 15.66 |
| 0.05 | −0.12 / 0.35 / 0.87 | 13.80 |
| 0.1 | −0.24 / 0.71 / 1.75 | 13.67 |
| 0.2 | −0.48 / 1.40 / 3.47 | 13.37 |
| **0.3026（= resize 的范数）** | −0.70 / 2.13 / 5.34 | **13.18** |
| 0.5 | −1.22 / 3.56 / 8.81 | 15.03 |
| **0.9262（初版，错）** | −2.26 / 6.61 / 16.62 | **24.13** |

**机理**：老词表的 0.926 是模型**训练出来的自信**，不是新 token 该有的起点。码本方向与 hidden
只是**部分**对齐（R²=0.40），范数一大，未被对齐的那 60% 就变成大幅随机 logits，淹没正确答案。
**尺度是放大器 —— 方向对错都被它放大。**

**现在的做法**：对齐 *resize 默认给新 token 的范数*（写入前实测 `emb.weight[orig:].norm().mean()`）。
这样与基线**同起点，唯一变量只剩方向** —— 干净的 A/B。实测该点 loss 13.18 < 基线 15.66，
**说明方向确实带信息**。

**② `<d_*>` 的 15 个消歧 token 无码本对应**
约 27% 商品 SID 需要它们（碰撞前缀）→ 保持随机方向但**尺度对齐**，否则 logits 偏小 3 倍。

### 1.4 实现的两个关键设计（避免隐含假设）

- **不依赖 `token 编号 = code + 1` 这个偏移**，而是从 `codes[i,lv]` + `index.json` 反推 `{level: {code: token}}`，并**断言自洽**（同一 code 在不同 item 上必须映射到同一 token）。
- **tie 红利**：`tie_word_embeddings=True`，写 `emb.weight` 自动同步 `lm_head`（同一块 tensor）→ 输入/输出两侧同时获得语义初值。

### 1.5 ⚠️ 实验前提（决定结论怎么解读）

**SFT 的第 2 个任务（sid↔title 互译）本身就是"让模型学 SID 语义"。码本初始化等于直接给答案。**

→ **只能作为独立消融**，不可与使用随机初始化的全参 SFT 直接比较"谁更好"。正确的解读是：

> "在已经知道 SID 语义结构的前提下，能省掉多少学习成本？"

### 1.6 进一步推论（更有价值的可能）

若初始化足够好，可能使 **"embedding 冻结 + 只训 LoRA"** 成立 → 彻底绕开 embedding 的 1.25 GB Adam 状态开销（当前 LoRA run 的最大单项优化器成本，见 §3）。

**验证路径**：`INIT_EMB=codebook FREEZE_OLD_EMB=True` 且额外冻结新 token 行 → 观察能否收敛。

## 3. LoRA 路线的显存事实（实测，写入备查）

### 3.1 为什么 LoRA 在当前配置下省不动显存

| | 全参 SFT（zero2 / 4 卡） | LoRA（1 卡） |
|---|---|---|
| **reserved/卡** | 20.38 GiB | 19.84 GiB |
| **每步**（同样全局 batch 1024） | 3.54 s | 9.77 s |

**根因**：`reserved` 不是活张量峰值，是分配器缓存水位（`sft.py:37` 的打印在 `empty_cache()` **之前**）。真实活张量峰值 ≈ 12.7 GiB（实测外推），其中：

```
参数 + 优化器状态      1.87 GiB   ← LoRA 唯一能动的部分
logits 链路            5.56 GiB   ← 18 字节/元素 × N × V，LoRA 碰不到
28 层激活值            ~3.0 GiB   ← LoRA 碰不到
分配器碎片             ~7.1 GiB
────────────────────────────────
reserved               ≈19.8 GiB
```

**每 token 成本 ≈ 4.8 MiB**（推导见 `RL_IDEAS.md` §10.1；⚠️ 该节的**字节数分解**有一处待复核 —— 但**总量是实测的**，本节这个结论不受影响）。LoRA 只能改"参数"那 12%，而 logits 链路（~55%）由 `B×L×V` 决定，与可训练参数量无关。

### 3.2 逐卡算账：LoRA 的收益被 zero2 分片吃掉了

```
每个被优化的参数 = 2B(梯度) + 8B(Adam m+v) + 4B(主权重,仅DS) = 14 字节
优化器状态是梯度的 4 倍 —— "省的是梯度"只说对了 20%

全参（4 卡 zero2）每卡：参数 1.2 + 梯度 0.30 + 主权重 0.60 + Adam 1.20 = 3.30 G
LoRA（1 卡，无分片）：  参数 1.2 + (LoRA .02 + emb .30) + (LoRA .08 + emb 1.25) = 2.85 G
差 = 0.45 G   ← 实测 0.54 GiB
```

**核心洞察：LoRA 和 ZeRO 分片作用在同一处（优化器状态），收益不可叠加。**

**embedding 那 1.25 GB 是当前 LoRA 最大的单项优化器开销**——Adam 按整块 tensor 分配状态，**梯度掩码不省内存**（掩码是行为约束，不是显存优化）。§1.6 的路径正是针对这一点。

## 4. 一句话备忘

- **码本初始化**：两空间语义对齐已实测（R²=0.40、level-0 命中 47.3%），实现已就位；它是"给答案"，只能作独立消融；真正的价值可能是**让 embedding 冻结成为可能**，从而消掉 1.25 GB 的 Adam 状态。
- **LoRA 的定位**：不是省资源，是**参数效率 + 多租户部署**。多租户还有坑——embedding 跟着 adapter 走（不同类目的 SID token 不同），共享 base 需先改设计。
- **优先级（2026-09-18 更新）**：**冻结 embedding（§1.6）** > lr 扫描 > FREEZE_OLD_EMB > r 扫描。
  ~~码本初始化~~ **已完成**（E1–E5）；而它的结论正好把 §1.6 顶了上来 —— 码本已能把 LoRA 拉到
  全参水平，下一步就是看能否**连 embedding 一起冻掉**，从而省掉那 1.25 GB 的 Adam 状态。
